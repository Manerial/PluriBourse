**Décision :** Tous les documents imprimés sont traduits (bon de dépôt, facture, reversement, rapports).

### 2026-06-08 — Architecture i18n : Option A (fichiers séparés)
**Décision :** Frontend ngx-translate (JSON) + Backend Spring MessageSource (.properties). Fichiers séparés — les traductions front et back sont de nature différente.

### 2026-06-08 — Éditions : contraintes de cycle de vie
**Décision :** Une seule édition active à la fois.
**Décision :** Fin de Post-vente = archivage automatique. Tous les documents sont générés dans les deux langues (EN + FR) au moment de l'archivage. L'édition passe en lecture seule. Suppression impossible.
**Décision :** Taux de commission instance-wide. Surcharge par édition reportée à une version ultérieure.
**Décision :** Le taux est saisi au setup de l'instance (défaut 20 %) et modifiable par l'admin jusqu'au début de la phase Dépôt. Une fois la phase Dépôt démarrée, le taux est figé pour cette édition — les vendeurs ne peuvent pas se retrouver face à un taux qu'ils n'ont pas accepté. Il s'applique à tous les articles de l'édition.

### 2026-06-09 — Rétention données à l'archivage (révisé)
**Décision :** FR-013 révisé. Clôture = génération PDFs EN+FR + passage en lecture seule. Les articles restent en base après clôture.
**Décision :** Action "Nettoyer l'édition" disponible post-clôture : supprime définitivement les articles de la base et désactive le rollback pour cette édition. Irréversible.
**Décision :** Commission appliquée normalement sur les articles incomplets vendus (prix affiché, taux standard).
**Décision :** Bilan journalier = jour calendaire.
**Décision :** Catalogue — prévention doublons (article déjà vendu ou déjà dans le panier). Recherche par numéro de code-barres ajoutée. Le numéro de code-barres doit apparaître sur l'étiquette.
**Décision :** Changement de phase pendant une transaction active = transaction annulée, erreur remontée au bénévole.

### 2026-06-09 — Catalogue articles (nouvelle feature F10)
**Décision :** Catalogue filtrable/triable accessible admin + bénévoles sur l'édition active. Filtres : nom, catégorie, table, statut vendu/invendu, complet/incomplet, vendeur. En phase Vente : ajout au panier depuis le catalogue (fallback code-barres illisible).

### 2026-06-08 — Rollback de phase
**Décision :** FR-011 révisé. Confirmation obligatoire avant toute transition (avance ET recul). Rollback possible d'une phase à la fois dans les deux sens : Clôturé→Post-vente, Post-vente→Vente, Vente→Dépôt. Les données sont toujours préservées. FR-083 supprimé.
**Décision :** Clôture = action manuelle admin ("Clôturer l'édition"), pas automatique. Génère les documents EN+FR, passe en lecture seule. Réversible (→ Post-vente).

### 2026-06-08 — F3 : articles et vendeurs
**Décision :** Format étiquette (centré) : nom édition — ligne vide — « --- Catégorie --- » — nom article + prix — « /!\ INCOMPLET » si applicable — Table n°X — ligne vide — graphique Code 128 — numéro de code-barres — ligne vide. Pas de nom vendeur (RGPD).
**Décision :** Attribution des tables automatique par le logiciel selon la catégorie. L'admin configure le mapping catégorie→table.
**Décision :** Articles modifiables et supprimables en phase Dépôt. Flag "complet/incomplet" + commentaire sur ce qui manque.
**Décision :** Profil vendeur = nom + prénom + email (tous obligatoires). Droit à l'effacement RGPD : suppression possible par l'admin.

### 2026-06-08 — Impression étiquettes : imprimante thermique 57mm

**Décision :** Impression déclenchée uniquement à la validation du dépôt d'un vendeur — réduit les impressions concurrentes.
**Décision :** Format du rouleau imprimé : [séparateur vendeur avec nom] + [étiquette article] + [séparateur article] + [étiquette article] + ... Ciseaux pour séparer.

**Décision :** Nom de l'édition retiré de l'étiquette article — pas de valeur ajoutée.
**Décision :** Contenu de l'étiquette centré sur le ticket.
**Décision :** Largeur du ticket configurable dans les paramètres admin (défaut 57mm) pour absorber un changement d'imprimante.
