- (decision) Les 6 surfaces admin (créer/modifier édition, gérer phases, gérer catégories, ajouter bénévole, réinitialiser mot de passe) passent de pages routées à dialogs mutualisés déclenchés par bouton depuis leur liste parente. Plus d'URL dédiée pour ces sous-routes.
- (decision) Nouveau composant comportemental DialogShellComponent : titre + croix de fermeture haut-droite + contenu projeté, sert de template à tous les dialogs de l'appli. Le dialog de confirmation et le dialog de reset password (déjà existants) adoptent ce même shell pour cohérence.
- (decision) Le composant dialog du design system (DESIGN.md) accueille désormais des formulaires plus riches (jusqu'à 5 champs) et un tableau dynamique éditable (catégories). Largeur max élargie à 640px pour ces cas, avec scroll interne du corps si le contenu dépasse la hauteur viewport, tout en gardant le focus trap sur l'ensemble du contenu scrollable.
- (decision) L'anti-pattern 'modals pour confirmer des actions non destructives' est nuancé : il concerne les confirmations d'action, pas les formulaires CRUD courts encapsulés en dialog. Les dialogs de confirmation de transition de phase restent inchangés.
- (event) Update ciblé initié suite à demande utilisateur en session de développement frontend (hors session UX standard) — scope limité à ces 6 surfaces, pas de refonte globale.
- (decision) DialogShellComponent est le conteneur standard pour tout dialog présent et futur de l'application, pas seulement les 6 surfaces converties + les 2 dialogs existants.
- (event) spines finalized (targeted update — dialogisation de 6 surfaces admin)
- (change) Retrait de la confirmation 'Fermer sans enregistrer ?' pour le formulaire édition (scope creep non demandé) — fermeture silencieuse, cohérente avec le comportement actuel de navigation hors page.
