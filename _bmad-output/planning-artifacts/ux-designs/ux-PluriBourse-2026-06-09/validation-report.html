PluriBourse — UX Design Validation Report

ux-designs/ux-PluriBourse-2026-06-09/DESIGN.md · EXPERIENCE.md
Run 2 · 2026-06-15

La paire de spines PluriBourse — après intégration des 10 corrections de la première passe — est globalement solide et prête pour le développement des flux opérationnels principaux. Tous les findings critiques et high bloquants de la première validation sont résolus sans exception. Les 6 Key Flows, la cohérence de navigation (aucune route orpheline), le vocabulaire métier stable et les patterns d'accessibilité sont confirmés par trois reviewers indépendants.

Cette deuxième passe est élargie aux lentilles cohérence interne et couverture PRD. Un seul point de blocage technique émerge : le token {typography.display-sm} dans le composant metric-tile n'existe pas dans le système de design — confirmé indépendamment par le rubric walker et le reviewer cohérence.

À traiter avant implémentation : 1 critical (token manquant), 4 high (exception états vides non documentée, variante Banner non documentée, FR-025 indicateur complet/incomplet hors Dépôt, FR-084 filtre vendeur Catalogue). 12 medium constituent un second niveau de priorité, à adresser sprint par sprint.

Rubric walker — 8 dimensions

1. Flow coverage

strong

Les 6 Key Flows couvrent l'ensemble des parcours utilisateurs. Chaque flow présente un protagoniste nommé, des étapes numérotées, un climax beat et un failure path. Aucune régression depuis la première passe.

low

Flow 2 sans failure path nommé

EXPERIENCE.md — Key Flow 2
Le lot incomplet (Marc) est couvert par State Patterns mais le flow ne nomme pas son failure path. Non bloquant.
Fix: Optionnel — "Failure: scanner déconnecté → [voir State Patterns]".

2. Token completeness

adequate

La régression critique de la première passe ({colors.error} sur un élément neutre) est résolue. Une nouvelle régression a été introduite lors de l'ajout des entrées comportementales : {typography.display-sm} dans le composant metric-tile ne résout pas. Ce niveau typographique n'existe pas dans le frontmatter DESIGN.md. Confirmé par deux reviewers indépendants.

critical

{typography.display-sm} inexistant dans DESIGN.md

EXPERIENCE.md ligne 157 — composant metric-tile
Scale typographique définie : display (32px/700), headline (24px/700), title-lg (18px/600), title-md, body-lg, body-md, label-lg, label-sm. Aucun niveau display-sm. Le frontmatter DESIGN.md metric-tile.value-font utilise déjà {typography.title-lg}.
Fix: Remplacer {typography.display-sm} par {typography.title-lg} dans EXPERIENCE.md ligne 157.

3. Component coverage

strong

Les 6 composants manquants de la première passe (segmented-control, banner, metric-tile, danger-zone, skeleton-row, list-row) ont été ajoutés avec des entrées comportementales complètes. Aucune régression.

4. State coverage

strong

L'état "Reversements — liste vide" et le comportement Enter dans "Somme remise" ont été ajoutés. Toutes les surfaces IA ont leurs états couverts. Aucune régression.

5. Visual reference coverage

strong

La règle "spine wins on conflict" est établie en blockquote en tête de la section IA. Toutes les références maquettes sont couvertes par cette règle globale.

6. Bloat & overspecification

strong

RFC 7807, verrou optimiste, garantie de non-double-vente, et SerialPort.getCommPorts() ont été retirés ou remplacés par des formulations neutres. "Non persistée en base" a été retiré. Aucune surspécification technique résiduelle.

7. Inheritance discipline

strong

L'entrée datée "Reversements sidebar" a été ajoutée au decision log. Les tokens résolvent vers des valeurs définies (sauf display-sm — voir §2). Nommage cohérent entre spines.

8. Shape fit

strong

Section Inspiration & Anti-patterns ajoutée après Foundation, conforme au modèle de référence. Les 8 sections DESIGN.md sont dans l'ordre canonique. Les 8 sections EXPERIENCE.md sont présentes. Aucune régression.

Lentilles supplémentaires

Cohérence interne

review-coherence.md

Les deux spines forment un système globalement solide : navigation complète (aucune route orpheline), vocabulaire métier stable, patterns de confirmation et toast cohérents. Trois zones de friction subsistent avant implémentation : le token display-sm inexistant (critical, confirmé §2), une exception non documentée dans Voice and Tone sur les états vides bloquants, et une ambiguïté de variante du composant Banner.

Verdicts par axe : Noms de composants — adequate · Tokens couleur/statut — adequate · Patterns UX — adequate · Navigation — strong · Vocabulaire métier — strong · Phases — adequate.

critical

{typography.display-sm} inexistant (confirmé §2)

EXPERIENCE.md — composant metric-tile
Token non défini dans DESIGN.md. Confirmé indépendamment par le rubric walker.
Fix: Remplacer par {typography.title-lg} — voir §2.
high

Exception états vides sans action non documentée

EXPERIENCE.md — Voice and Tone
Voice and Tone énonce "Jamais un état vide sans sortie" mais trois états documentés n'ont pas d'action proposée (/volunteer/waiting en Préparation, Reversements liste vide, Catalogue post-Archivage). Ces cas sont métier-justifiés mais créent une contradiction formelle.
Fix: Ajouter une note d'exception dans Voice and Tone : "Exception : les états structurellement bloquants (phase non ouverte côté bénévole, édition archivée) n'ont pas d'action proposée — le message explicatif suffit."
high

Variante Banner (info vs warning) non documentée

EXPERIENCE.md — Component Patterns Banner + Édition archivée — vue détail
Banner utilisé dans deux contextes avec des tokens différents : variante warning ({colors.warning} / {colors.on-warning}) pour Catégories verrouillées ; variante informationnelle ({colors.primary-container}) pour Édition archivée. Aucune variante documentée dans DESIGN.md ni EXPERIENCE.md.
Fix: Ajouter dans la définition Banner (EXPERIENCE.md) une section "Variantes" : warning (Catégories verrouillées) et info (Édition archivée, tokens primary-container / on-primary-container).
medium

Segmented control — tokens divergents entre DESIGN.md et EXPERIENCE.md

DESIGN.md frontmatter · EXPERIENCE.md — Component Patterns
EXPERIENCE.md : segment actif "fond {colors.primary}, texte blanc". DESIGN.md frontmatter : active-background: '{colors.primary-container}', active-foreground: '{colors.on-primary-container}'. Deux specs contradictoires.
Fix: Aligner EXPERIENCE.md sur DESIGN.md frontmatter (primary-container / on-primary-container), ou mettre à jour DESIGN.md et documenter l'exception.
medium

Dualité sémantique warning / primary-container

DESIGN.md frontmatter — colors
warning: '#FFF4EE' et primary-container: '#FFF4EE' ont des valeurs hex identiques. Banner utilise {colors.warning}, status-chip-warning utilise {colors.primary-container}. Confusion pour les développeurs.
Fix: Documenter dans DESIGN.md Colors que warning est un alias intentionnel de primary-container, ou fusionner les deux tokens.
medium

Bouton "Confirmer" de l'action Non réclamé en primary vs pattern irréversible

EXPERIENCE.md — Key Flow 3
L'action "Non réclamé" est irréversible. Les autres actions irréversibles utilisent error pour le bouton de confirmation. Le choix primary pour "Non réclamé" n'est pas documenté comme exception.
Fix: Documenter l'exception ("irréversible mais non destructif = primary suffisant") dans DESIGN.md Do's and Don'ts, ou aligner sur error.
medium

Référence "Clean Edition" orpheline dans Interaction Primitives

EXPERIENCE.md — Interaction Primitives
"Clean Edition" apparaît comme exemple d'action irréversible mais ce terme n'existe plus dans EXPERIENCE.md v2026-06-15 (renommé "Archiver l'édition").
Fix: Remplacer "Clean Edition" par "Archiver l'édition".
medium

Contraintes de phase absentes de 3 composants

EXPERIENCE.md — Page Rapports · Page Reversements · Fiche Catégories & Tables
Les composants Page Rapports (inaccessible en Préparation/Dépôt), Page Reversements (Post-vente + Clôturée uniquement), et Fiche Catégories & Tables (lecture seule de Dépôt à Clôturée) ne précisent pas leurs contraintes de phase, contrairement à l'IA.
Fix: Ajouter dans chaque composant une note "(phase X+ uniquement — entrée masquée dans la sidebar les autres phases)".
low

notification-inline — casse variable dans EXPERIENCE.md

EXPERIENCE.md — plusieurs sections
Nommé "Notification inline", "notification inline (variante erreur)", "notification inline avertissement" selon les sections. Kebab-case dans DESIGN.md frontmatter.
Fix: Uniformiser en notification-inline dans les mentions EXPERIENCE.md.

high

FR-025 — Indicateur complet/incomplet non modifiable hors phase Dépôt

EXPERIENCE.md — composant Catalogue / liste filtrée
Le PRD permet de modifier l'indicateur complet/incomplet et le commentaire en phases Vente, Post-vente et Clôturée. Aucun chemin UX défini dans EXPERIENCE.md pour cette action hors Dépôt.
Fix: Ajouter dans le composant Catalogue une colonne d'actions avec "Modifier statut" (accessible en toutes phases), ouvrant un dialog ou inline edit limité aux champs complet/incomplet et commentaire.
high

FR-084 — Filtre "nom du vendeur" absent du composant Catalogue

EXPERIENCE.md — composant Catalogue / liste filtrée
Le composant liste les filtres disponibles mais n'inclut pas le filtre "nom du vendeur" requis par FR-084.
Fix: Ajouter "nom du vendeur" dans la liste des filtres du composant Catalogue.
medium

FR-055 — Génération PDF bilan d'édition non décrite dans le flow de clôture

EXPERIENCE.md — composant Contrôle de phase
La génération automatique du bilan d'édition PDF (deux langues EN+FR) au moment de la clôture n'est pas spécifiée dans le composant Contrôle de phase — ni spinner, ni toast de confirmation.
Fix: Enrichir le composant "Contrôle de phase" avec état de clôture : spinner pendant la génération + toast "Bilan d'édition généré (EN + FR)".
medium

FR-045 — Étiquette thermique lot sans spec visuelle différenciante

EXPERIENCE.md — composant Formulaire lot
L'étiquette d'un article de lot doit afficher "Prix du lot : X€" et "Lot indivisible : X/N" à la place d'un prix individuel. Aucune spec de différenciation dans EXPERIENCE.md.
Fix: Ajouter dans le composant "Formulaire lot" un tableau comparatif étiquette standard vs étiquette lot.
medium

FR-019 — Champs vendeur et validations absents du formulaire dépôt

EXPERIENCE.md — composant Formulaire dépôt
Les champs obligatoires du profil vendeur (nom, prénom, email, téléphone) et leurs validations (format email, format téléphone) ne sont pas spécifiés.
Fix: Ajouter la liste des champs et leurs règles de validation dans le composant Formulaire dépôt.
medium

FR-041 — Structure de la facture acheteur non spécifiée

EXPERIENCE.md — composant Panier POS (état post-validation)
La structure de la facture acheteur (liste articles + prix, total, nom association, date, lots sur une ligne) n'est spécifiée que dans le PRD. EXPERIENCE.md décrit uniquement le bouton "Imprimer la facture".
Fix: Ajouter dans le composant Panier POS (état post-validation) une note sur les champs obligatoires du PDF facture.
medium

FR-014 — Suppression d'édition sans contrainte UX post-Préparation

EXPERIENCE.md — composant Page Éditions — liste
Le comportement du bouton "Supprimer" en phase post-Préparation n'est pas spécifié (absent ? désactivé avec tooltip ?).
Fix: Préciser que l'action "Supprimer" est absente ou désactivée (+ tooltip) pour toute édition ayant dépassé la phase Préparation.
medium

FR-030 — Structure du rouleau thermique non documentée dans EXPERIENCE.md

EXPERIENCE.md — Interaction Primitives "Impression"
La structure séquentielle du rouleau (séparateur vendeur → étiquettes → séparateur article) n'est documentée que dans le PRD, alors qu'elle conditionne la lisibilité en phase Dépôt.
Fix: Ajouter dans Interaction Primitives "Impression" une note sur la structure du rouleau par vendeur.
low

FR-027 — Layout étiquette standard non spécifié dans EXPERIENCE.md

EXPERIENCE.md — composant Formulaire dépôt
Ordre des champs, mention INCOMPLET conditionnelle, barcode XXXX-XXXX, absence du nom vendeur (RGPD) — spécifiés dans le PRD uniquement.
Fix: Ajouter une note de structure étiquette dans le composant Formulaire dépôt.
low

FR-024 — Suppression d'article sans spec UX complète

EXPERIENCE.md — composant Catalogue (admin phase Dépôt)
Ni CTA décrit dans le catalogue, ni dialog de confirmation, ni post-état pour la suppression d'article en phase Dépôt.
Fix: Ajouter bouton "Supprimer l'article" (danger zone), dialog de confirmation, et toast post-suppression dans le composant Catalogue phase Dépôt.
low

FR-010 — Unicité édition active sans contrainte UX

EXPERIENCE.md — composant Page Éditions — liste
Le comportement du bouton "Créer une édition" quand une édition active existe déjà n'est pas spécifié.
Fix: Bouton désactivé + tooltip si une édition active existe.
low

FR-061 — Sélecteur de rôle non contraint à la création d'utilisateur

EXPERIENCE.md — composant Page Utilisateurs
Le sélecteur de rôle ne précise pas que le rôle "Admin" ne doit pas être proposable (un seul compte admin par instance).
Fix: Préciser que le rôle "Admin" est absent du sélecteur lors de la création d'un compte bénévole.
low

FR-050 — Contenu du bilan de vente sans spec formelle de composant

EXPERIENCE.md — composant Récapitulatif reversement imprimable
Le contenu du bilan (articles vendus, invendus avec table, total brut, commission, net) est décrit narrativement dans Flow 5 sans spec de composant formelle.
Fix: Ajouter dans le composant "Récapitulatif reversement imprimable" une liste des champs attendus du bilan.
