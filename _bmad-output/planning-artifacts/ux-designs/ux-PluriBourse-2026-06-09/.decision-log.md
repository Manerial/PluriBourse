# Journal des Décisions — UX PluriBourse

## Session 2026-06-09

### Capturé depuis le brain dump
- Style : minimaliste, moderne, intuitif, minimum de clics
- Workflow : guidé, centré sur la phase (Inscription V2 > Dépôt > Vente > Post-vente > Clôture)
- Animations : minimales — outil, pas une vitrine
- Images : aucune, éventuellement un logo
- Contraste : fort — le public cible inclut des bénévoles âgés avec une mauvaise vision
- Navigation au clavier : importante mais pas critique ; lecteur d'écran minimum obligatoire, davantage si possible
- Ambiance : chaleureuse, éviter les bleus froids et le noir & blanc

### Direction couleur
- **Retenu : F — Rouge Corail**

- Primaire clair : #C44626 · Primaire sombre : #F07040 (éclairci pour contraste WCAG AA)
- Palette : #FFF4EE · #FCA47E · #C44626 · #8C2910 · #1A0A05
- Rejetés : Ambre (trop doré), Terracotta (trop terreux), Rose Carmin (trop rose), Fuchsia (trop vif), Olive (identité nature ≠ projet), Indigo (bleu trop froid pour l'identité)

### Formes, ombres, icônes
- **Arrondis : Moyen** — cards 12px, inputs 8px, boutons 8px, badges pill (999px)
- **Ombres : Standard Material** — `0 4px 16px rgba(28,10,5,.14), 0 1px 4px rgba(28,10,5,.08)` sur cartes et modals
- **Icônes : Material Symbols Outlined** — inclus Angular Material, aucune dépendance supplémentaire

### Voix & ton
- Langue UI : EN/FR (ngx-translate) — documents imprimés : EN/FR (Spring MessageSource)
- Ton : vouvoiement en français pour tous les messages, confirmations, états vides, erreurs
- Microcopy : direct, impératif pour les actions ("Valider le dépôt"), nominatif pour les labels
- Pas de jargon technique visible dans l'interface

### Architecture de l'information — écrans
**Sidebar Admin :** Vendeurs · Articles · Éditions · Rapports · Utilisateurs · Paramètres

*(Mise à jour 2026-06-11 : "Reversements" ajouté dans la sidebar Admin, visible uniquement en phases Post-vente et Clôturée — masqué les autres phases.)*

**Éditions — fiche détail (création + édition) :**

- Informations générales (nom)
- Catégories & Tables : config catégories + mapping catégorie→tables ; à la création option "Copier depuis édition clôturée" ou from scratch ; éditable jusqu'au démarrage phase Dépôt
- Contrôle de phase : phase active + bouton transition + dialog confirmation

**Bénévole — écrans par phase :**

- Dépôt : recherche vendeur → création si absent → saisie articles → validation + impression
- Vente : caisse (scanner + panier + lots + validation + facture)
- Post-vente : liste reversements → fiche reversement (Régler / Non réclamé)
- Toutes phases : Catalogue (+ ajout panier en Vente)

**Partagés :** Connexion · Mon compte (langue)

### Structure de navigation
- **Retenu : Option 3** — topbar partagée (logo + indicateur de phase + badge rôle + profil) pour Admin et Bénévole
- Sidebar sombre contextuelle Admin uniquement (sections : Édition active → Vendeurs, Articles, Reversements, File d'impression ; Gestion → Éditions, Rapports, Utilisateurs, Config)
- Bénévole : topbar seule + plein écran centré sur la tâche active, pas de sidebar
- Un seul `LayoutComponent` partagé — sidebar conditionnelle `*ngIf="isAdmin"`

### Catégories & Tables — mise à jour 2026-06-11

- **Relation catégorie ↔ table** : many-to-many — une table peut être partagée entre plusieurs catégories. Aucun indicateur visuel de partage (silencieux).
- **Tables = labels numériques libres** (Option A retenue) : pas d'entité `Table` séparée. `TableAssignment { category_id, table_number (entier), edition_id }`. L'admin saisit des numéros directement dans la config catégorie.
- **Format des identifiants de table** : entiers uniquement (pas de lettres ni de texte libre en v1).
- **Saisie** : chips en saisie libre — l'admin tape un numéro, appuie sur Entrée, le chip s'affiche. Suppression via × sur le chip.
- **Phase** : modifiable en Préparation, verrouillé dès Dépôt (bannière « Catégories verrouillées »). Retour arrière Dépôt → Préparation déverrouille.
- **Côté bénévole (dépôt)** : table auto-assignée affichée en texte inline sous/après le sélecteur de catégorie.

### Identité (Q&A)
- Identité : fraîche/vierge — pas de marque existante, multi-association → éviter une identité de marque forte
- Plateforme : web desktop uniquement (pas de mobile, pas de tablette)
- Densité : confortable
- Admin vs Bénévole : même identité visuelle ; indicateur de rôle visible requis
- Thèmes : clair + sombre tous les deux supportés

### Inspiration & Anti-patterns
- **Inspirations positives** : Stripe Dashboard (clarté des données financières, hiérarchie typographique forte), Square POS (simplicité du flux de caisse, feedback immédiat), Notion (navigation sidebar plate et lisible).
- **Anti-patterns à éviter** : interfaces POS surchargées avec des dizaines de boutons visibles simultanément ; couleurs statuts qui empruntent la couleur primaire (corail = marque, pas statut) ; wizards multi-étapes pour des actions simples (le dépôt reste sur une page) ; modals pour confirmer des actions non destructives (préférer l'inline ou le toast).
